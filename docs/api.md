# API contract

Local development: Vite proxies `/api` to FastAPI on port 8000. The selected Render setup mounts `/api` and serves the compiled website from the same container. OpenAPI and `/docs` exist in local development only; a hosted site (`STATIC_SITE_DIR` set) hides them. Routes below omit the public `/api` prefix. Resident and staff routes use an HttpOnly `session` cookie. For authenticated POST and PUT requests, send the readable `csrf_token` cookie value in `X-CSRF-Token`. Registration and login set both cookies. Staff/admin accounts are provisioned through the CLI.

## Staff jurisdiction

The server places each report in the barangay whose boundary contains its pin; a client cannot set it. In the table above, "staff" means staff of the report's barangay. For any other report, including one with no barangay because its pin is outside every boundary, report routes answer 404, as they do for another resident's report. Lists, the brief and notifications leave those reports out. Administrators see everything, and staff with no barangay see nothing. Until the first barangay is loaded none of this applies, and all staff see all reports.

A case stays in one barangay: automatic suggestions stay inside it, `/cases/link` refuses a pair from different barangays, and a report sent with the `case_id` of a case across a border is saved on its own instead of joining it. `/cases/map` stays shared across barangays, since it has no photos, descriptions or names.

Confirming a duplicate pair from different barangays answers 409, though it can still be rejected, and loading boundaries removes pending suggestions that a border now separates. When staff reject an "I see this too" link, the report's barangay is worked out again from its own pin. Staff of a new barangay aren't notified of that move. `/reports/{id}/duplicates/generate` still compares against every barangay inside frozen `duplicates.py`, but `cases.py` answers both duplicate read routes and leaves out suggestions the caller could not open.

Categories: `flooding`, `fallen_trees`, `broken_streetlights`, `exposed_wiring`, `potholes`, `uncollected_garbage`, `damaged_signage`, `other`. The AI suggests from all eight; residents can change any suggestion. Status sequence: `Pending`, `Under Verification`, `Accepted`, `In Progress`, `Resolved`; verification may instead end in `Rejected`. A report has distinct `model_category`, `resident_category`, and `verified_category`. The API never accepts a client-supplied model category: submission reuses the server's own analysis of the same photo from the preview (kept 30 minutes by photo hash), or runs only the local checker when there is none. On `/reports/predict`, `prediction_available:false` means neither model answered; on a report, it means no checker embedding was stored. An uncertain prediction can be available with `model_category:null`. Another resident's report or image returns 404.

Current duplicate and chat behavior is intentionally explicit: without a validated embedding model, duplicate lookup returns `embedding_available:false`, empty suggestions, and `manual_review_required:true`. Chat uses deterministic guidance when Workers AI is unconfigured, times out, fails, exhausts the Free allocation (`429`), or returns an invalid response; that returns `llm_available:false` and `source:"deterministic"`. A valid Workers AI answer returns `llm_available:true` and `source:"workers_ai"`.

Each successful staff status transition creates an in-app notification for the report owner in the same database transaction. Notifications contain only report ID, status, and timestamps; another account cannot list or mark them read. While on screen, the app checks notifications every 5 seconds, on page load and when the tab regains focus.

Optional generic guidance uses Cloudflare's [`@cf/mistralai/mistral-small-3.1-24b-instruct` REST model](https://developers.cloudflare.com/workers-ai/models/mistral-small-3.1-24b-instruct/), the same model that writes photo descriptions (confirmed to work on a Workers Free account; it replaced the Gemma-based SEA-LION model because Gemma 3 is not allowed there). Set `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_WORKERS_AI_TOKEN` to enable it. The resident's message goes to the model after a best-effort removal of emails, phone numbers and report IDs, so names or addresses typed into chat can still reach Cloudflare. The model judges whether the message is about the app and answers as Kap; otherwise, or when it is unavailable, a fixed reply answers. Report status stays database-only and never calls the model. Requests time out after 15 seconds. Cloudflare documents a [10,000 neuron daily Free allocation](https://developers.cloudflare.com/workers-ai/platform/pricing/) and a [429 response when it is exhausted](https://developers.cloudflare.com/workers-ai/platform/errors/); this prototype does not query the account's billing plan, so do not configure a paid account if charges must be impossible. No Workers AI call is made unless both credentials are configured.
